第一层

第一层给了这些东西：

  • generate-plaintexts.py
  • encrypt.py
  • key-*.pem
  • ciphertext-*.bin

这一层表面上是在考秘密共享 + RSA + AES，实际上核心是：

  1. 识破假的门限共享
  2. 找弱 RSA 公钥并恢复私钥
  3. 解出若干份明文 share

第二步

encrypt.py 里面分了两种情况：

1. 当 n.bit_length() >= 2048 时：

  • 随机生成 32 字节 AES key
  • 用 RSA-OAEP 加密 AES key
  • 再用 AES-GCM 加密明文

2. 当 n.bit_length() < 2048 时：

  • 随机生成 16 字节 AES key
  • 直接做 pow(key, e, n) 的“裸 RSA”
  • 再用 AES-GCM 加密明文

所以我们只要能把 RSA 私钥还原出来，就能解出 AES key，再解出 plaintext。

这一层的技术路线非常明确：

  • 先破 RSA
  • 再破 AES-GCM
  • 最后还原 share

第四步：用弱 key 去试所有 ciphertext

这里有一个容易踩的坑：

不能假设 ciphertext-i.bin 一定对应 key-i.pem。

  • 如果最后 AES-GCM 验证通过，就说明匹配成功
